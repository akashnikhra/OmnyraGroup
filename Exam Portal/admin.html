CSV format guide
  1. Header row (exact, UTF-8): id,question,optionA,optionB,optionC,optionD,correctIndex,rationale,topic,difficulty,marks — legacy alias option1,option2,option3,option4 is also accepted on upload.
  2. One row per question (max 500 rows + header). Keep the header as row 1; data starts row 2.
  3. Quoting: wrap any field containing a comma, quote, or line-break in "double quotes"; escape a literal quote as "". Example: "Access to sensitive data, criticality of service, and substitutability".
  4. correctIndex is 0-based: 0=A, 1=B, 2=C, 3=D.
  5. marks is an integer 1–100; difficulty is easy|medium|hard; question and rationale need ≥ 10 chars; all 4 options must be distinct.
  6. Save as UTF-8 (with or without BOM). Contract: BACKEND.md §4 — CSV columns.

Missing server file? The buttons fall back to a built-in template download automatically.

3 · Publish

  1. Save the download as Exam Portal/questions/<exam-id>.v<YYYY-MM-DD>.json.
  2. Add/edit the entry in questions/manifest.json (id, title, file, version, questionCount, durationMinutes, passPercent, status: "published") and bump updatedAt.
  3. Validate: node "Exam Portal/tools/validate-questions.mjs" "Exam Portal/questions/<file>.json" — must print PASS.
  4. Commit (feat: prefix), push to main — GitHub Pages serves it statically; the catalog picks it up with zero code change.
  5. TODO backend: POST the same JSON to the question-bank API instead (see README + BACKEND.md).
